Keel Skills is MIT-licensed and actively seeks contributions. The two highest-value contributions are **policy packs** — ready-made `AGENT_POLICY.md` templates for new stacks — and **implementations for other runtimes**, bringing the Keel governance model to agent SDKs, CI gates, and other harnesses. Both are easy to start and immediately useful to the community.

## Ground rules

These rules apply to all contributions:

- **No telemetry or network calls** are added without an explicit, documented, opt-in design.
- **Attribution:** keep the MIT notice; a visible credit to *Keel Skills by Esteban Aguilar* is the norm (see the `NOTICE` file).
- **Discussion and questions:** open a GitHub issue.

## When improving skills

The three skills are the reference implementation of the Keel governance model. When editing them, follow these four rules:

1. **Keep them generic** — no project-, client-, or company-specific data ever goes in a skill. That belongs in the consumer's `AGENT_POLICY.md`.
2. **Keep each skill's concept disjoint from the others** — don't blur authorization, delegation, and context discipline together.
3. **Update `CHANGELOG.md` and bump the version** in `plugin.json` and `.claude-plugin/marketplace.json` together.
4. **Never blur authorization, delegation, and context discipline together** — each skill owns one concept and one concept only.
